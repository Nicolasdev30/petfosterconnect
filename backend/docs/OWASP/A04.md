# A04 - Insecure Design

## Comment on a conçu une architecture sécurisée

### Le problème

Un mauvais design peut créer des failles de sécurité même avec du bon code. Il faut :

- Une architecture claire et maintenable
- Une séparation des responsabilités
- Une gestion d'erreurs robuste
- Des bonnes pratiques de développement

### Notre solution

#### 1. Architecture MVC bien structurée

Structure du projet : `src/`

```
src/
├── index.js              # Point d'entrée, configuration serveur
├── config/               # Configuration (BDD, Swagger)
├── models/               # Modèles de données (Sequelize)
├── controllers/          # Logique métier
├── routes/               # Définition des endpoints
└── middlewares/          # Fonctions intermédiaires
```

**Séparation claire des responsabilités :**

- **Models** : Structure des données et relations
- **Controllers** : Logique métier et traitement des requêtes
- **Routes** : Définition des endpoints et middlewares
- **Middlewares** : Authentification, validation, gestion d'erreurs

#### 2. Configuration centralisée et sécurisée

Fichier : `src/index.js`

```javascript
// Configuration des variables d'environnement
dotenv.config();

// Middlewares sécurisés
app.use(
  cors({
    origin: process.env.FRONTEND_URL || "http://localhost:5173",
  })
);

app.use(express.json());
app.use(express.urlencoded({ extended: true }));
```

**Bonnes pratiques appliquées :**

- Variables d'environnement pour la config
- CORS configuré avec origine spécifique
- Parsing JSON sécurisé
- Documentation Swagger intégrée

#### 3. Routage organisé par domaine

Fichier : `src/routes/index.js`

```javascript
// Organisation modulaire des routes
router.use("/auth", authRoutes); // Authentification
router.use("/animals", animalRoutes); // Gestion animaux
router.use("/associations", associationRoutes); // Gestion associations
router.use("/requests", requestRoutes); // Demandes d'adoption
router.use("/admin", adminRoutes); // Administration
```

**Avantages de cette organisation :**

- Code modulaire et maintenable
- Responsibilities claires par domaine
- Facilité de tests et débogage
- Routes sécurisées par middleware

#### 4. Gestion d'erreurs robuste

Fichier : `src/middlewares/errorHandler.js`

```javascript
// Middleware 404 pour routes non trouvées
export const notFound = (req, res, next) => {
  const error = new Error(`Route non trouvée - ${req.originalUrl}`);
  res.status(404);
  next(error);
};

// Gestionnaire global d'erreurs
export const errorHandler = (err, req, res, next) => {
  let statusCode = res.statusCode === 200 ? 500 : res.statusCode;

  // Gestion spécifique des erreurs Sequelize
  if (err.name === "SequelizeValidationError") {
    statusCode = 400;
    message = err.errors.map((error) => error.message).join(", ");
  }

  // Pas de stack trace en production
  res.status(statusCode).json({
    success: false,
    message: message,
    ...(process.env.NODE_ENV === "development" && { stack: err.stack }),
  });
};
```

#### 5. Contrôleurs avec gestion d'erreurs systématique

Pattern utilisé dans tous les contrôleurs :

```javascript
export const createAnimal = async (req, res, next) => {
  try {
    // 1. Validation des permissions
    if (!req.user.id_association) {
      return res.status(403).json({
        success: false,
        message: "Vous devez être membre d'une association",
      });
    }

    // 2. Logique métier
    const animal = await Animal.create({
      name,
      species,
      breed,
      age,
      id_association: req.user.id_association,
    });

    // 3. Réponse structurée
    res.status(201).json({
      success: true,
      message: "Animal créé avec succès",
      data: { animal },
    });
  } catch (error) {
    // 4. Délégation au gestionnaire d'erreurs
    next(error);
  }
};
```

#### 6. Modèles avec contraintes et validations

Exemple : `src/models/User.js`

```javascript
const User = sequelize.define("User", {
  email: {
    type: DataTypes.STRING(100),
    allowNull: false,
    unique: true,
    validate: {
      isEmail: true,
    },
  },
  password: {
    type: DataTypes.TEXT,
    allowNull: false,
  },
  id_role: {
    type: DataTypes.INTEGER,
    allowNull: false,
    references: {
      model: Role,
      key: "id_role",
    },
  },
});
```

#### 7. Middlewares chainés pour la sécurité

Exemple de protection multicouche :

```javascript
// Routes animaux avec sécurité progressive
router.post(
  "/",
  authenticateToken, // 1. Vérification JWT
  requireRole("association"), // 2. Vérification rôle
  validateAnimal, // 3. Validation données
  createAnimal // 4. Contrôleur métier
);
```

#### 8. Logging et monitoring

Pattern de logging sécurisé :

```javascript
// Logs d'informations (pas de données sensibles)
console.log("✅ Modèles synchronisés avec la base de données");

// Logs de sécurité pour audit
console.log(`🔒 ADMIN ACTION: User ${id} deleted by admin ${req.user.email}`);

// Logs d'erreurs (uniquement en dev)
if (process.env.NODE_ENV === "development") {
  console.error("🔥 Erreur:", err);
}
```

### Bonnes pratiques implémentées

#### Design sécurisé

- **Fail securely** : Erreurs 403/401 par défaut
- **Defense in depth** : Validation à plusieurs niveaux
- **Least privilege** : Permissions minimales par rôle
- **Separation of concerns** : MVC strict

#### Code quality

- **Error handling** : try/catch + middleware global
- **Input validation** : Express-validator sur toutes les routes
- **Environment config** : Variables d'environnement
- **Documentation** : Swagger pour l'API

#### Sécurité opérationnelle

- **Health check** : Endpoint `/api/health`
- **Structured responses** : Format JSON consistent
- **No information leakage** : Pas de stack trace en prod
- **Audit logging** : Actions sensibles tracées

### Ce qu'on évite (mauvais design)

❌ **Monolithe** : Tout dans un seul fichier  
❌ **Global state** : Variables globales  
❌ **Hard-coded values** : Pas de config en dur  
❌ **Silent failures** : Erreurs non gérées  
❌ **Mixed concerns** : Logique métier dans les routes  
❌ **No validation** : Données non validées

### Architecture resiliente

Notre design permet :

- **Maintenabilité** : Code modulaire et testé
- **Scalabilité** : Séparation claire des responsabilités
- **Sécurité** : Validation et autorisation à tous les niveaux
- **Observabilité** : Logs et monitoring intégrés
- **Robustesse** : Gestion d'erreurs complète

### Points d'amélioration pour la production

- **Rate limiting** : Limitation des requêtes par IP
- **Request ID** : Traçabilité des requêtes
- **Metrics** : Monitoring des performances
- **Circuit breaker** : Protection contre les pannes en cascade
- **Graceful shutdown** : Arrêt propre du serveur

Résultat : Architecture robuste qui évite les failles de conception.
