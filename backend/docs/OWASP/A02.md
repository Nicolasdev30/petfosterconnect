# A02 - Cryptographic Failures

## Comment on a sécurisé la cryptographie dans l'app

### Le problème

Les données sensibles (mots de passe, tokens) doivent être protégées avec de la crypto solide. Sinon :

- Les mots de passe peuvent être lus en cas de leak de BDD
- Les tokens peuvent être forgés
- Les communications peuvent être interceptées

### Notre solution

#### 1. Hachage des mots de passe avec Argon2

Fichier : `src/controllers/authController.js`

On utilise Argon2 qui est recommandé par l'OWASP (plus sécurisé que bcrypt).

**À l'inscription :**

```javascript
import argon2 from "argon2";

// 4. Sécuriser le mot de passe avec un hash
const hashedPassword = await argon2.hash(password);

// 5. Stocker le hash en BDD (jamais le password en clair)
const user = await User.create({
  // ...
  password: hashedPassword,
});
```

**À la connexion :**

```javascript
// 4. Vérifier que le mot de passe est correct
const isValidPassword = await argon2.verify(user.password, password);
if (!isValidPassword) {
  return res.status(401).json({
    message: "Email ou mot de passe incorrect",
  });
}
```

Pourquoi Argon2 ?

- Résistant aux attaques par dictionnaire
- Résistant aux attaques rainbow tables
- Coût de calcul ajustable (protection contre la force brute)
- Recommandé OWASP 2023

#### 2. Tokens JWT sécurisés

Fichier : `src/controllers/authController.js` et `src/middlewares/auth.js`

**Génération de token :**

```javascript
const generateToken = (userId) => {
  return jwt.sign({ id: userId }, process.env.JWT_SECRET, {
    expiresIn: "7d", // Expiration automatique
  });
};
```

**Vérification de token :**

```javascript
// 2. Vérifier et décoder le token JWT
const decoded = jwt.verify(token, process.env.JWT_SECRET);
```

Protection JWT :

- Secret fort dans la variable d'environnement `JWT_SECRET`
- Expiration automatique (7 jours)
- Signature vérifiée à chaque requête
- Gestion des erreurs (token expiré, invalide)

#### 3. Protection des données sensibles

**Exclusion des mots de passe :**
Dans tous les retours API, on exclut le password :

```javascript
// Dans les modèles Sequelize
const userWithRole = await User.findByPk(user.id_user, {
  attributes: { exclude: ["password"] },
});

// Dans les contrôleurs
const { password: _, ...userWithoutPassword } = user.toJSON();
```

**Variables d'environnement :**
Fichier : `.env.example`

```bash
# JWT secret fort (à changer en production)
JWT_SECRET=your-super-secret-jwt-key-change-in-production

# BDD credentials sécurisées
DB_PASSWORD=your_password
```

#### 4. Configuration sécurisée

**CORS configuré :**

```javascript
app.use(
  cors({
    origin: process.env.FRONTEND_URL || "http://localhost:5173",
  })
);
```

**Gestion des erreurs JWT :**

```javascript
// Gestion des erreurs JWT spécifiques
if (error.name === "JsonWebTokenError") {
  return res.status(403).json({
    message: "Token invalide",
  });
}
if (error.name === "TokenExpiredError") {
  return res.status(403).json({
    message: "Token expiré",
  });
}
```

### Ce qu'on a sécurisé

- **Mots de passe** : Jamais stockés en clair, toujours hashés avec Argon2
- **Tokens** : JWT signés avec secret fort, expiration automatique
- **API responses** : Mots de passe exclus de toutes les réponses
- **Environnement** : Secrets dans des variables d'environnement
- **CORS** : Origine frontend configurée

### Points de sécurité respectés

1. **Pas de crypto faible** : Argon2 au lieu de MD5/SHA1
2. **Secrets gérés** : Variables d'environnement pour JWT_SECRET
3. **Données sensibles protégées** : Passwords jamais renvoyés
4. **Tokens expirés** : JWT avec expiration automatique
5. **Algorithmes récents** : Argon2 (winner Password Hashing Competition)


### En production (à ajouter)

- **HTTPS obligatoire** : Toutes les communications chiffrées
- **JWT_SECRET complexe** : Généré aléatoirement, long (256+ bits)
- **Rotation des secrets** : Changer JWT_SECRET régulièrement
- **Headers sécurisés** : helmet.js pour les headers HTTP

Résultat : Aucune donnée sensible n'est stockée ou transmise en clair.
