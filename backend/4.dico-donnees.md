# Le Dictionnaire de données : liste des entités et de leurs attributs (Fiche Récap)

## table: rôle

### Description:Définit les rôles des utilisateurs dans le système

| Champ   | Type        | Contraintes      | Description                |
| ------- | ----------- | ---------------- | -------------------------- |
| id_role | SERIAL      | PRIMARY KEY      | Identifiant unique du rôle |
| label   | VARCHAR(50) | NOT NULL, UNIQUE | Libellé du rôle            |

### Relations:

1 => N avec user (Un rôle peut être attribué à plusieurs utilisateurs)

## Table: Association

### Description: Informations des associations gérant les animaux

| Champ          | Type         | Contraintes      | Description                         |
| -------------- | ------------ | ---------------- | ----------------------------------- |
| id_association | SERIAL       | PRIMARY KEY      | Identifiant unique de l'association |
| name           | VARCHAR(100) | NOT NULL, UNIQUE | Nom de l'association                |
| email          | VARCHAR(100) | NOT NULL, UNIQUE | Email de contact                    |
| phone          | VARCHAR(20)  | NULL             | Numéro de téléphone                 |
| address        | TEXT         | NOT NULL         | Adresse complète                    |

### Relations:

1 => N avec user (Une association peut avoir plusieurs gestionnaires)
1 => N avec animal (Une association gère plusieurs animaux)

## Table: User

### Description: Utilisateurs de la plateforme (familles d'accueil et gestionnaires d'associations)

| Champ          | Type         | Contraintes                            | Description                                    |
| -------------- | ------------ | -------------------------------------- | ---------------------------------------------- |
| id_user        | SERIAL       | PRIMARY KEY                            | Identifiant unique de l'utilisateur            |
| first_name     | VARCHAR(100) | NOT NULL                               | Prénom                                         |
| last_name      | VARCHAR(100) | NOT NULL                               | Nom de famille                                 |
| email          | VARCHAR(100) | NOT NULL, UNIQUE                       | Adresse email                                  |
| password       | TEXT         | NOT NULL                               | Mot de passe hashé (Argon2)                    |
| id_role        | INTEGER      | NOT NULL, FK → role(id_role)           | Référence vers le rôle                         |
| id_association | INTEGER      | NULL, FK → association(id_association) | Association de rattachement (NULL pour foster) |

### Contraintes supplémentaires:

Si id_role = 1 (foster) alors id_association = NULL
Si id_role = 2 (association) alors id_association NOT NULL
ON DELETE RESTRICT sur id_role
ON DELETE SET NULL sur id_association

### Relations:

N => 1 avec rôle
N => 1 avec association (optionnel)
1 => N avec request (Un utilisateur peut faire plusieurs demandes)

## Table: Animal

### Description: Animaux disponibles pour l'accueil ou l'adoption

| Champ          | Type         | Contraintes                                                         | Description                    |
| -------------- | ------------ | ------------------------------------------------------------------- | ------------------------------ |
| id_animal      | SERIAL       | PRIMARY KEY                                                         | Identifiant unique de l'animal |
| name           | VARCHAR(100) | NOT NULL                                                            | Nom de l'animal                |
| species        | VARCHAR(50)  | NULL                                                                | Espèce                         |
| breed          | VARCHAR(100) | NULL                                                                | Race                           |
| age            | INTEGER      | CHECK (age >= 0)                                                    | Âge en années                  |
| description    | TEXT         | NULL                                                                | Description détaillée          |
| photo_url      | TEXT         | NULL                                                                | URL de la photo                |
| status         | VARCHAR(20)  | CHECK (status IN ('disponible', 'accueilli')), DEFAULT 'disponible' | Statut de l'animal             |
| id_association | INTEGER      | NOT NULL, FK → association(id_association)                          | Association propriétaire       |

### Valeurs autorisées:

Status: 'disponible', 'accueilli'

### Contraintes supplémentaires :

ON DELETE RESTRICT sur id_association

### Relations:

N => 1 avec association
1 => N avec request (Un animal peut recevoir plusieurs demandes)

## Table request

### Description : Demandes d'accueil faites par les familles pour les animaux

| Champ      | Type        | Contraintes                                                             | Description                        |
| ---------- | ----------- | ----------------------------------------------------------------------- | ---------------------------------- |
| id_request | SERIAL      | PRIMARY KEY                                                             | Identifiant unique de la demande   |
| created_at | TIMESTAMP   | DEFAULT CURRENT_TIMESTAMP                                               | Date et heure de création          |
| status     | VARCHAR(20) | CHECK (status IN ('pending', 'accepted', 'refused')), DEFAULT 'pending' | Statut de la demande               |
| message    | TEXT        | NULL                                                                    | Message personnalisé de la famille |
| id_user    | INTEGER     | NOT NULL, FK → user(id_user)                                            | Famille demandeur                  |
| id_animal  | INTEGER     | NOT NULL, FK → animal(id_animal)                                        | Animal demandé                     |

### Valeurs autorisées:

status : 'pending', 'accepted', 'refused'

### Contraintes supplémentaires :

ON DELETE RESTRICT sur id_user et id_animal

### Relations:

N → 1 avec user
N → 1 avec animal

### Cardinalités détaillées:

| Relation             | Cardinalité | Description                                     |
| -------------------- | ----------- | ----------------------------------------------- |
| role ↔ user          | 1,N → 1,1   | Un rôle pour plusieurs users, un user a un rôle |
| association ↔ user   | 1,N → 0,1   | Une association pour plusieurs gestionnaires    |
| association ↔ animal | 1,N → 1,1   | Une association gère plusieurs animaux          |
| user ↔ request       | 1,N → 1,1   | Un user peut faire plusieurs demandes           |
| animal ↔ request     | 1,N → 1,1   | Un animal peut recevoir plusieurs demandes      |

## Règles de gestion

### Contraintes fonctionnelles:

1. Utilisateurs famille (id_role = 1) ne peuvent pas avoir d'association (id_association = NULL)
2. Gestionnaires association (id_role = 2) doivent être rattachés à une association
3. Animaux ne peuvent avoir que les statuts 'disponible' ou 'accueilli'
4. Demandes ne peuvent avoir que les statuts 'pending', 'accepted' ou 'refused'
5. Âge animal doit être positif ou nul

## Workflow des statuts :

Animal : 'disponible' → 'accueilli'
Request : 'pending' → 'accepted' OU 'refused'
Quand une demande est acceptée, l'animal peut passer à 'accueilli'

## Contraintes d'intégrité:

Unicité : emails users, emails associations, noms associations
Référentielles : toutes les clés étrangères avec actions ON DELETE appropriées
Domaines : contrôle des valeurs autorisées pour les statuts

## Sécurité

### Authentification:

| Élément     | Spécification                            | Exemple               |
| ----------- | ---------------------------------------- | --------------------- |
| Algorithme  | Argon2id                                 | Recommandé OWASP 2025 |
| Paramètres  | m=65536, t=3, p=4                        | Sécurité élevée       |
| Format hash | $argon2id$v=19$m=65536,t=3,p=4$salt$hash | Standard Argon2       |

## Données sensibles :

Mots de passe : jamais stockés en clair
Emails : uniques et utilisés pour l'authentification
Informations personnelles : prénom, nom, adresse association
